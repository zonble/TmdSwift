# TMD 語言規格（TmdSwift 實作版）

版本：0.1（對應目前 TmdSwift parser）  
語言：繁體中文

## 1. 文件目的

本文件定義目前 TmdSwift 所接受的 TMD（Text Music Description）文字格式。
文件描述的是「目前實作的行為」，不是未來功能的提案。歷史設計、原始 TMDLang
文件以及尚未實作的語法，另見 [`Band-Score.syntax.zh_TW.md`](Band-Score.syntax.zh_TW.md)。

TMD 是用純文字描述歌曲結構、樂器段落、首調唱名、和弦與播放順序的格式。
一個 TMD 檔案解析後會形成 `Sheet`，再由 MIDI、MusicXML、LilyPond、ABC 或
WAV 輸出模組使用。

## 2. 最小檔案結構

```text
::SCORE::
** 歌曲名稱 **
!= 120
?= C
<4/4>

段落名稱:樂器名稱@|0|{
    <4*>
    1 2 3 4
}

-> 段落名稱 ->#
```

檔案必須以 `::SCORE::` 開頭。其後可出現歌曲標題、速度、調性、拍號、段落
和播放順序。解析器目前允許這些項目的順序較為寬鬆；同一項目重複出現時，
後出現的值會覆蓋前一個值。

## 3. 空白與註解

空白、Tab、換行都會被忽略，因此下列寫法在詞法上等價：

```text
!=120
!= 120
! = 120
```

區塊註解使用 `/*` 和 `*/`，可以跨越多行：

```text
/* 這段文字不會成為音樂資料 */
```

目前沒有行註解語法。未閉合的區塊註解會一路忽略到檔案結尾。

## 4. 歌曲標題、速度、調性與拍號

### 4.1 標題

```text
** 三天三夜 **
```

`**` 之間的識別字、數字和音符數字會組合成標題；多個詞之間以單一空格
保存。標題不是必要欄位，未提供時 `Sheet.name` 為空字串。

### 4.2 速度

```text
!= 133
!= 120.5
```

速度保存為 BPM 的 `Double`。整數和小數皆可。段落內也可使用 `{!=145}` 或
`{!+30}` 改變後續播放的絕對或相對速度。

### 4.3 調性

```text
?= A'
? = C
```

調性保存為字串，不在 parser 層驗證調號是否合理。因此 `C`、`A'`、`Bb` 或
其他可被讀成識別字的內容都可能被接受。調性轉換 `{?+5}` 是播放順序中的
相對轉調，不是這裡的檔頭調性欄位。

### 4.4 拍號

```text
<4/4>
<3/4>
```

前一個數字是每小節拍數，後一個數字是拍子的音符值。拍號保存為
`Beat(count:noteValue)`。

## 5. 段落與軌道

段落語法如下：

```text
段落名稱:樂器名稱@{
    section+
}

段落名稱:樂器名稱@|起始小節|{
    section+
}
```

例如：

```text
intro:Piano@|0|{
    <4*>
    1 2 3 4
}

intro:Guitar@|+4|{
    <16*>
    1_ - 1_ -
}
```

欄位意義如下：

| 欄位 | 意義 |
| --- | --- |
| 段落名稱 | 例如 `intro`、`A`、`chorus` |
| 樂器名稱 | 例如 `Piano`、`Guitar`、`CHORD` |
| 起始小節 | 以整數表示；省略時為 `0` |

起始位置可以是正數、零或負數；負數表示提前進場，例如 `@|-1|`。

同一個段落名稱可以有多個樂器段落。它們會各自保存為一個 `Paragraph`，
不會在 parser 層合併。

## 6. Section 與基本節奏單位

每個 section 以 `<n*>` 開始：

```text
<4*>
1 2 3 4

<16*>
1_ - 1_ -
```

`n` 會保存為 `Section.noteLength`，表示此段落使用的基本細分單位。
section 會持續讀取音樂單位，直到遇到下一個 `<n*>`、段落結尾 `}` 或檔案結尾。

section 中可使用 `|` 作為排版用小節線。它在目前 parser 中會被忽略：

```text
| 1 2 | 3 4 |
```

### 6.1 段落內 directive

directive 可放在 section 的音樂單位之間，位置以它前面的基本單位數表示：

```tmd
<4*>
1 2 {!=140} 3 4
{!+10}
{?+2}
{?=D}
{<3/4>}
```

支援的種類包括絕對／相對速度、絕對／相對調性，以及局部拍號。MIDI 會將
速度與拍號寫入 conductor track；MusicXML、LilyPond 和 ABC 會輸出相應標記。

## 7. 音樂單位

### 7.1 首調唱名音符

基本音符是 `1` 到 `7`：

```text
1 2 3 4 5 6 7
```

升降記號必須直接接在音級後面：

```text
1'     /* 升 Do */
2,     /* 降 Re */
```

八度以 `^` 或 `_` 表示，每一個符號代表一個八度：

```text
1^     /* 高一個八度 */
1^^    /* 高兩個八度 */
1_     /* 低一個八度 */
1__    /* 低兩個八度 */
1'^    /* 升 Do，高一個八度 */
```

升降記號和八度記號的順序是固定的：先寫升降記號，再寫八度記號。
同一音符重複出現升降記號時，最後一個記號決定 accidental；八度符號則累加。

### 7.2 和弦

和弦使用中括號：

```text
[Cmaj7]
[Am]
[1]
[6m]
```

中括號內的內容會原樣保存為字串（前後空白會移除），parser 不驗證和弦名稱
或和弦是否符合調性。

### 7.3 延音／複製線

單一 `-` 會解析為 tie：

```text
1 - - -
[Cmaj7] -
```

實際延音時值由 exporter 依前後音樂單位與 section 的節奏解讀。

### 7.4 連音／節奏群組

括號內放置多個音樂單位，再以 `%(...)` 指定群組所佔的基準長度：

```text
(1 2 3)%(--)
(7, 1)%(--)
```

`%(--)` 中每一個 `-` 代表一個基準長度，因此上例的 `length` 是 `2`。
括號內可包含音符、和弦、tie，以及其他可被 parser 讀取的音樂單位。

若沒有連音標記，單一音樂單位會形成一個 `length = 1` 的群組：

```text
1 2 [C] -
```

等同於四個各含一個 unit 的 `UnitGroup`。

## 8. 播放順序與轉調

播放順序由 `->` 開始，以 `->#` 結束：

```text
-> intro -> A -> B ->#
```

段落名稱會保存為 `Order.name`：

```text
-> intro
```

相對轉調使用：

```text
-> {?-3}
-> {?+3}
```

內容會保存為 `Order.relative` 的字串，例如 `-3` 或 `+3`。絕對轉調使用：

```text
-> {?=C}
-> {?=A'}
```

內容會保存為 `Order.absolute` 的字串。

`->#` 是播放順序終止標記。parser 目前遇到它就結束整個 Sheet 的解析；
因此它後面的文字不會被處理。

## 9. AST 對照

| TMD 概念 | Swift 型別 |
| --- | --- |
| 拍號 | `Beat` |
| 音符 | `Note` |
| 音符／和弦／tie | `Unit` |
| 連音群組 | `UnitGroup` |
| `<n*>` 與其內容 | `Section` |
| 段落與樂器軌 | `Paragraph` |
| 播放順序 | `Order` |
| 完整歌曲 | `Sheet` |

目前 `Unit` 支援 `.note`、`.chord`、`.tie`、`.rest` 和 `.percussion`；歌曲
metadata 保存於 `Sheet.metadata`，段落 directive 保存於 `Section.directives`。

## 10. Show Program

非音樂演出控制內容可以使用三引號區塊：

```tmd
show:Lighting@intro{
"""
cue black
wait 4
"""
}
```

內容原樣保存於 `Paragraph.showProgram`，`@` 後的識別字保存於
`Paragraph.executionTime`。本版本不解讀 body 內的控制語言，實際設備執行器
可在 AST 之上另行實作。

## 11. 解析與編碼

`TmdParser` 可從以下來源解析：

- Swift `String`
- `Data`
- 本地檔案 URL
- 檔案路徑或 `file://` URL 字串

以 `Data` 解析時，工具會嘗試偵測文字編碼，支援 UTF-8、Big5、GB18030 等
常見編碼。解析失敗時目前 API 以 `nil` 表示；parser 尚未提供行號、欄號或
結構化診斷訊息。

## 12. 相容性與未來擴充

本文件的版本只保證目前 TmdSwift parser 已經能夠解析並保存在 AST 中的語法。
未來若加入新語法，應遵守以下原則：

1. 不改變既有合法 TMD 的音樂意義。
2. 新增 AST 型別或欄位時，明確記錄 exporter 的處理方式。
3. 為每個新語法加入 parser、formatter 與至少一個 exporter 的測試。
4. 將原始 TMDLang 語法和 TmdSwift 擴充語法分開標示。
5. 需要無法相容的變更時，提升規格版本並提供 migration 說明。

## 13. 完整範例

```tmd
::SCORE::
** 範例歌曲 **
!= 120
?= C
<4/4>

intro:CHORD@|0|{
    <4*>
    [Cmaj7] - [Am] -
}

intro:Piano@|0|{
    <16*>
    1 2 3 4 (5 6 7 1^)%(--)
}

-> intro -> {?+3} -> intro ->#
```

這個檔案包含一個四四拍歌曲、兩條 `intro` 軌道、一組和弦、一組旋律、
一個兩基準單位長度的連音群組，以及播放中途上升三個半音的相對轉調指令。
